# 让 AI 验收 rig-gateway 连接

在能调用 MCP 工具或运行本地 Python 的 AI 客户端中发送下面这段提示词。已有目标配置时可直接使用。也可以把本页链接发给能读取 GitHub 的 AI，并让它执行「首次连接验收」。

## 首次连接验收

```text
请用中文完成一次 rig-gateway 只读连接验收，并报告实测结果。

1. 优先使用客户端已经配置的 rig-gateway。获取该服务器的完整工具清单，调用 system_info 读取 hostname，调用 host_status 读取 policy.sandbox_root。按仓库 skills/rig-remote-ops/SKILL.md 权限表中各级的完整工具名称核对清单。若客户端只展示部分工具，将权限级别记为“未核实”。

2. 若客户端没有这个 MCP 连接，但已知目标私网 HTTP 地址，可在控制端从 rig-gateway 仓库根目录运行下面的标准库验证器。将占位符替换为实际值：
   python skills/rig-remote-ops/scripts/verify_endpoint.py --host <目标主机地址> --port <端口> --auth none --tier <预期级别> --expect-hostname <预期主机名>
   直连无认证的网关使用此命令。HTTPS 或认证代理使用已有客户端的认证配置，凭据保留在客户端。缺少目标地址时向我询问；仅在我指定本机试用时使用 127.0.0.1。

3. 未指定预期级别时按默认 Tier 1 核对。工具清单与预期不符时，报告多出或缺少的工具并保留该结果。若目标机名未知，可省略 --expect-hostname，报告服务器返回的机名，并标注“身份待确认”。只有完整机名与独立提供的预期值一致时，才标注“身份已确认”。

4. 最后给出连接结果、实测主机名及身份核对结果、工具数及权限级别、沙箱路径。保留服务器返回的“未配置”状态；没有读到的字段写“未核实”。失败时指出第一个失败的步骤和下一项检查，例如 TCP 已通但 MCP 握手失败。

本次操作限于工具发现和只读状态查询。部署、重启、文件写入、远程命令、键盘输入和设备动作均需另行安排。
```
