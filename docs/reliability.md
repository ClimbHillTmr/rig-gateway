# rig-gateway 的连接恢复与功能设计

[中文首页](../README.md) · [English](reliability.en.md) · [操作手册](operations.md)

一台目标机可以同时有多个网关实例。一次现场故障中，目标机在私网在线，控制端保留了默认端口，而已部署实例监听另一个端口。在部署端口上，MCP 握手、工具清单和主机名都通过了验证。修复发生在控制端的连接条目。重启目标机服务无法改变控制端保存的 URL。

## 现在可以使用的检查

在控制端仓库根目录运行。先从**部署记录**取得主机、端口、完整 Windows 机名和预期级别。以下 PowerShell 变量在控制端设置。验证器只检查指定的一个直连 HTTP 端点，默认执行只读的 `system_info` 调用。

```powershell
$gatewayIP = Read-Host 'Deployed host IP'
$gatewayPort = Read-Host 'Deployed gateway port'
$expectedName = Read-Host 'Expected Windows hostname'
$tier = Read-Host 'Expected tier (1, 2, or 3)'
python skills/rig-remote-ops/scripts/verify_endpoint.py --codex-entry rig-gateway --host $gatewayIP --port $gatewayPort --expect-hostname $expectedName --tier $tier --auth none --connect-attempts 3
```

- **配置漂移。** `--codex-entry` 读取 Codex 的有效条目，检查启用状态、传输、主机、端口和路径。端口不一致时先报告两个端口并退出，凭据不会写入诊断信息。去掉此选项可独立验证部署记录中的端点。确认目标身份、权限和运行中的沙箱后，在客户端更正 URL，保留已有的认证设置和工具过滤，再重新运行完整检查。
- **短暂中断。** `--connect-attempts 3` 仅在首次 TCP 连接失败时最多尝试三次，间隔 1 秒和 2 秒。握手后的请求不会因这个参数被重复发送。默认仍为一次。
- **最终验收。** 配置正确、端点可用和当前客户端会话可用是三项独立证据。重连客户端，取得完整的 `tools/list`，再调用 `system_info` 和 `host_status`。核对机名、工具名称和沙箱目录。脚本可在控制端启动流程中调用，失败返回非零。仓库未安装后台监控。

## 建议的下一阶段设计

| 故障或需求 | 负责组件与行为 | 验收条件 |
|---|---|---|
| 部署改端口，客户端仍用旧值 | 部署器输出私有的连接记录，含 URL、实例标识、主机名、权限级别、沙箱和版本。由控制端对照可信记录。自动改写仅面向已授权的本地条目，核对目标后仅更新 URL，并检查并发修改。 | 两个不同端口的实例可区分。错误机名、权限或沙箱阻止切换。已有请求头、凭据引用和工具过滤保留。 |
| HTTP 会话过期或网络恢复 | 客户端负责重新初始化、协商版本、发送 initialized 通知，重新发现工具。会话失效与身份认证失败分别处理；401/403 交给既有认证流程。 | 模拟旧会话返回 404，新会话完成只读验收。网络抖动时退避有上限。 |
| 写入、移动、命令或按键后丢失响应 | 客户端将结果标为「执行状态未知」，先通过只读观察核对效果。需要可靠重试的业务操作单独设计操作 ID、去重和结果保留。 | 服务端已执行、回执丢失时，同一操作不会被自动再发一次。 |
| 服务进程在，握手持续超时 | 目标机上的服务管理器分别记录进程存活和本机 MCP 探针结果。仅在授权的恢复策略下，确认连续本机失败、无在途作业后再重启指定实例，并限制重启次数。 | 单个控制端离线不会触发真机重启。本机反复失败时可查看探针、退出原因、日志及恢复结果。 |
| 想知道连接到了哪个版本、当前能做什么 | 保留现有 15 个工具的契约。在初始化元数据或只读 MCP resource 中提供构建号、实例标识、启动时间和已启用级别。状态工具分别报告桌面会话、可用依赖及文件策略。 | 能区分「已注册截图工具」和「当前有可截图的交互桌面」，现有客户端的精确工具清单仍然有效。 |
| 多人操作、文件传输和追溯 | 按角色隔离实例及网络端口。需要桌面输入时由单个操作员持有控制权。跨机二进制传输若进入产品，应明确方向、大小限制、哈希与覆盖策略。审计记录只保留操作 ID、耗时、结果和必要的身份信息。 | 只读用户接触不到操作端口，两个客户端不会同时发送桌面输入；可追溯超时操作且日志不含文件正文或凭据。 |

实施顺序建议先统一部署记录与客户端校验，再补会话恢复和故障注入测试，最后引入目标端守护及跨机传输。MCP 的 tools、resources 和 prompts 按能力协商；新功能应对应明确的客户端需要。当前安装提示词放在 GitHub 上，因此网关尚未启动时 AI 也能读取。[MCP 生命周期](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle) · [Streamable HTTP 与会话恢复](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)
